# 적용 대기 중인 제안

사용자에게 시험판을 보여 줬지만 아직 "적용해줘" 답을 받지 않은 변경을 보관하는 폴더다. 게임은 이 폴더를 쓰지 않는다.
사용자가 적용을 허락하면 아래 순서대로 반영하고, 반영한 제안은 이 폴더에서 지운다.

## 새 초원 배경 (2026-11-13 시험)

- 파일: `meadow-background.patch`(코드 변경), `meadow-background-compare.png`(왼쪽 지금 배경 / 오른쪽 새 배경)
- 바뀌는 것: `game.js`의 배경 그리기 부분(`BACKGROUND_SCALE`, `buildBackground`)만이다. 게임 규칙은 바뀌지 않는다.
  - 배경 점 하나를 화면 4칸에서 2칸으로 바꿔 펫·시설과 점 크기를 맞춘다(배경 그림 240×150 → 480×300).
  - 크고 작은 얼룩을 겹친 명암에 4×4 체크무늬(디더링)로 단계 경계를 섞는다.
  - 끝이 밝은 풀 포기 무리, 클로버, 들꽃 무리(흰·노랑·분홍·보라)를 넣는다.
- 사용자 반응: 시험판과 비교 그림을 보냈고, 적용 여부와 꽃 양·색 조정 의견을 기다리는 중이다.
- 적용 방법(저장소 폴더에서):

```bash
git apply proposals/meadow-background.patch
```

- 적용하면 검사 2개를 의도적인 변경에 맞게 고쳐야 한다(검사를 느슨하게 만드는 것이 아니라 바뀐 사양에 맞추는 것).
  - `6-6 배경: 1/4 크기(240×150) …` → 배경 그림 크기 기대값을 `480,300,480,300`으로, 항목 이름도 "1/2 크기(480×300)"로 고친다.
  - `5-4 흙길 없음: 배경은 풀밭 초록뿐` → 들꽃은 초록이 아니므로 "흙길 색(갈색 계열: 빨강 > 초록 > 파랑, 빨강 200 미만, 빨강−파랑 40 초과) 점이 하나도 없음"과 "초록이 가장 진한 점이 97% 이상"으로 바꾼다.
- 그다음 `node tests/regression.js`로 실패 0을 확인하고, `IMPLEMENTATION_STATUS.md` 8장, `README.md`, `TEST_RESULTS.md`, `HANDOFF.md`의 배경 설명(1/4 크기, 4배)을 고친다.
